## Sprint 01 — Foundation ✅

**Цель:** запускаемое Android/iOS-приложение с правильной архитектурой,
локальной базой, темами и навигацией.

Сделано:

* Flutter-проект, `pubspec.yaml` с зафиксированными семействами зависимостей
  (Riverpod, go_router, Drift, sqlite3_flutter_libs, uuid), линтер со strict-режимом;
* Clean Architecture + feature-first: `app`, `core`, `domain`, `data`,
  `providers`, `features`;
* Drift: 10 таблиц, индексы, миграционная стратегия, 5 реализаций репозиториев,
  мапперы;
* доменные сущности `Account`, `Contact`, `MessageThread`, `Message`,
  `Attachment`, настройки;
* контракт `MailProvider` + `ProviderCapabilities` + определение провайдера по
  домену (Gmail / Яндекс / Mail.ru / Outlook / прочее);
* дизайн-система: семантические токены, две темы, типографика, отступы, радиусы,
  контраст под тестом;
* навигация: нижняя панель из четырёх разделов + push-маршруты;
* экраны: Диалоги (поиск, Focus Mode, список), Люди, Избранное, профиль
  человека, переписка, Smart Composer, настройки, тема, безопасность, аккаунты,
  добавление аккаунта, о приложении;
* демо-данные через реальные мапперы (идемпотентный сид);
* тесты: unit + repository + state + widget, включая архитектурный guard
  `tool/check_structure.sh`;
* документация: `README`, `AGENTS.md`, 9 документов в `docs/`.

Осознанно не сделано: реальная авторизация, отправка, групповая синхронизация,
push, FTS5. Экраны честно сообщают об этом.

**Критерий приёмки:** `flutter analyze` чистый, `flutter test` зелёный,
приложение открывается и показывает диалоги из локальной базы в обеих темах.

## Sprint 03 — Mail Core ✅

Сделано:

* `SecureTokenStorage` (Keychain `first_unlock_this_device` /
  EncryptedSharedPreferences) с проверкой доступности и in-memory реализацией
  для тестов.
* `providers/oauth`: PKCE (S256), `state`, обмен кода и refresh с injectable
  `http.Client`.
* `providers/gmail`: endpoints, `GmailApi` (list/get/history/modify/send/
  attachment, повтор после 401 через refresh), `GmailMessageParser` (MIME-дерево,
  RFC 2047, cp1251/koi8-r), `GmailMailProvider` (контракт + инкрементальный
  курсор).
* `providers/mime`: сборка RFC 5322 с `Message-ID`, `In-Reply-To`,
  `References`; Bcc только в конверте.
* `services/sync`: `MailSyncService` (инкрементально по `historyId`, полная
  сверка, устаревший курсор → реконкайл), `SyncStateStore`,
  `ConversationRouter` (provider thread → `In-Reply-To` → `References` → новый).
* UI: экран подключения Gmail с реальными стадиями, экран «Синхронизация»
  (последняя синхронизация, ошибки, полная сверка), честное поведение для
  провайдеров, которых ещё нет.
* Тесты: `test/providers/{pkce,oauth_client,mime_builder,gmail_parser}_test.dart`,
  `test/services/{conversation_router,mail_sync_service}_test.dart`.

Критерий выполнен по коду: письма из реального Gmail попадают в базу и в список
без дубликатов. Отправка писем сознательно перенесена в Sprint 05.

Дополнительно закрыто (вне спринтов, для проверки на устройстве):

* `tool/platform/prepare_android.py` — патч сгенерированного `android/`:
  `minSdk 23`, `allowBackup=false`, intent-filter для OAuth-redirect,
  `flutter_deeplinking_enabled=false`, `<queries>` для браузера.
* `.github/workflows/build-apk.yml` — `flutter analyze`, тесты, debug APK,
  iOS-компиляция без подписи; артефакт `mellow-debug-apk`.
* `app_links` — возврат из браузера после согласия Google без ручной вставки
  URL (ручной путь остался как резерв).
* Экран **Настройки → Данные → Хранилище**: реальные размеры базы, число
  писем/диалогов/людей, удаление локальных писем по аккаунту и целиком
  (сервер не затрагивается).
* `docs/INSTALL.md` — установка APK и первый запуск.

## Sprint 05 — Composer & Attachments

Сделано (отправка и ответы):

* **Отправка через Gmail**: `SendController` кладёт письмо в базу со статусом
  `sending`, отдаёт адаптеру и ставит `sent` только после того, как сервер
  принял письмо (спец. §6.5). При ошибке письмо остаётся в диалоге со статусом
  `failed`, текст не теряется, кнопка «Повторить» переиспользует ту же строку —
  дублей не появляется.
* **Ответ**: кнопка «Ответить» в переписке и долгое нажатие на конкретное
  письмо открывают редактор с заполненными «Кому», `Re:`-темой и заголовками
  `In-Reply-To`/`References`; ответ попадает в тот же диалог. Ответ на своё
  письмо уходит адресатам, а не самому себе.
* **Честность**: для Яндекса, Mail.ru, Outlook и IMAP редактор прямо говорит,
  что отправка появится в спринте 06, и не пытается «отправить».
* **Прочитано при открытии**: переписка помечает свои непрочитанные письма
  прочитанными локально (сервер обновляет движок синхронизации).
* Исправлено: ошибка получателя исчезает при редактировании адреса, состояние
  отправки не перетекает из одного сеанса редактора в другой.

Остаётся:

* Черновики в базе (сейчас текст живёт в пределах экрана) и офлайн-очередь
  с повторной отправкой после обрыва связи.
* Вложения: скачивание, кеш, белый список типов, лимиты.
* Ответ всем и пересылка.

Критерий: сценарий D (потеря соединения) даёт корректный статус без дубликатов.

## Sprint 09 — In-app updates ✅ ТЗ / ⏳ код

Полное ТЗ — [`UPDATES.md`](UPDATES.md). Кратко:

* CI публикует релиз `build-<sha7>` с APK; приложение читает GitHub Releases.
* Проверка на старте, при возврате из фона (не чаще раза в 6 часов) и вручную.
* Найденное обновление: **плашка в «Диалогах»** + системное уведомление
  (когда появится инфраструктура уведомлений из Sprint 07).
* Загрузка с прогрессом, отменой и проверкой размера; затем передача APK
  системному установщику Android.
* Данные при установке поверх сохраняются; подпись сборок стабилизируется
  ключом из секретов репозитория.
* Тихая установка без согласия пользователя не делается: Android этого не
  позволяет, и обещать это было бы ложью.

Критерий: сценарий §11 `UPDATES.md` проходит на телефоне — от плашки до
установки новой сборки с сохранением всех данных.
