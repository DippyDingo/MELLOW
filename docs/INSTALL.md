# Установить Mellow на телефон

Два пути: **скачать готовый APK из CI** (быстро, ничего устанавливать не нужно)
или **собрать самому** (нужен Flutter). Ниже оба.

---

## Вариант A. Готовый APK из GitHub Actions

APK собирается автоматически при каждом изменении в ветке
`arena/ef9ea789-mellow` и складывается в артефакт сборки.

**Проверенная сборка:** `mellow-b14464b-debug.apk` (88 МБ, debug),
прогон [45215924220](https://github.com/DippyDingo/MELLOW/actions/runs/45215924220) —
все три задачи зелёные: анализ, 236 тестов, APK, iOS (компиляция).

1. Откройте
   [`Actions → Build installable APK`](https://github.com/DippyDingo/MELLOW/actions/workflows/build-apk.yml).
2. Выберите последний успешный запуск (зелёная галочка, ветка
   `arena/ef9ea789-mellow`).
3. Внизу страницы, блок **Artifacts** → скачайте `mellow-debug-apk.zip`.
4. Распакуйте: внутри `mellow-<sha>-debug.apk`.
   Артефакты хранятся 30 дней; если ссылка устарела — запустите workflow
   заново (**Run workflow**), сборка займёт около 5 минут.
5. Перекиньте `.apk` на телефон (Telegram «Избранное», почта, кабель, Google
   Drive — любым способом).
6. На телефоне откройте файл. Android спросит разрешение
   «Устанавливать из неизвестных источников» — разрешите для файлового
   менеджера/браузера, которым открываете, и подтвердите установку.

Если хочется собрать с настоящим входом в Gmail — запустите workflow вручную:
**Run workflow** → поле `GOOGLE_CLIENT_ID` → ваш client id. Подробности в
[`VERIFY.md` §5](VERIFY.md#5-подключение-реального-gmail).

### Что вы увидите без ключей Google

Приложение запустится и работает целиком на демо-данных; экран подключения
Gmail честно скажет, что в этой сборке нет `GOOGLE_CLIENT_ID`. Это не баг:
ключи не хранятся в репозитории.

### Почему debug, а не release

Release-сборка требует собственного ключа подписи и постоянного хранения
пароля от него; для проверки на своём телефоне это лишний риск потерять
доступ к обновлениям. Debug-APK подписан стандартным ключом CI, поэтому
каждая новая сборка ставится поверх предыдущей без удаления данных.

## Вариант B. Собрать APK самому

```bash
git clone https://github.com/DippyDingo/MELLOW.git
cd MELLOW
git checkout arena/ef9ea789-mellow
bash tool/bootstrap.sh          # pub get, генерация Drift, android/, проверки, тесты

# debug APK: ставится на любой телефон, живёт рядом с релизной версией
flutter build apk --debug
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

Либо просто `flutter run` с подключённым по USB телефоном (включите
«Отладка по USB» в настройках разработчика).

### Собрать с входом в Gmail

```bash
export MELLOW_OAUTH_SCHEME=com.googleusercontent.apps.<ваш-id>   # для патчера манифеста
bash tool/bootstrap.sh

flutter build apk --debug \
  --dart-define=GOOGLE_CLIENT_ID=<ваш-id>.apps.googleusercontent.com \
  --dart-define=GOOGLE_REDIRECT_URI=com.googleusercontent.apps.<ваш-id>:/oauth2redirect
```

`tool/bootstrap.sh` прописывает этот же scheme в `AndroidManifest.xml`
(через `tool/platform/prepare_android.py`), иначе браузер после согласия
Google не сможет вернуться в приложение.

### iOS

Нужен Mac с Xcode и **Apple ID** (бесплатный аккаунт разработчика подходит для
установки на своё устройство, срок подписи — 7 дней).

```bash
flutter run -d <device-id>      # подпись настроится в Xcode → Runner → Signing
```

Без Apple ID собрать `.ipa` для установки на телефон нельзя — CI собирает iOS
только для проверки компиляции (`--no-codesign`).

## Первый запуск: что проверить

1. Приложение открывается, видны четыре вкладки: **Диалоги**, **Люди**,
   **Избранное**, **Настройки**.
2. В «Диалогах» — демонстрационная переписка (только в debug-сборке).
3. **Настройки → Данные → Хранилище** показывает реальные цифры: сколько писем
   и диалогов лежит на устройстве и сколько занимает база.
4. **Настройки → Оформление** — переключите тему, закройте и откройте
   приложение: выбор сохранился.
5. **Настройки → Аккаунты → Добавить**: введите свой Gmail. Если сборка с
   ключами — откроется браузер с согласием Google; после подтверждения
   приложение вернётся само и начнёт загрузку писем.
6. **Настройки → Синхронизация → Синхронизировать сейчас**: появится отчёт
   (сколько писем получено), а в «Диалогах» — реальные письма.
7. Нажмите «Синхронизировать сейчас» ещё дважды: количество диалогов не должно
   вырасти (дедупликация).
8. Откройте любой диалог: письма помечаются прочитанными, внизу — поле
   «Ответить…». Нажмите его: откроется редактор с уже заполненными «Кому» и
   темой `Re: …`, а не пустая форма нового сообщения.
9. Отправьте ответ на свой адрес: он появится в диалоге с галочкой, а через
   несколько секунд подтянется и с сервера. Долгое нажатие на любое письмо
   отвечает именно на него, а не на последнее в переписке.
10. Проверьте честность: **Настройки → Аккаунты → Добавить** и введите адрес
    Яндекса или Mail.ru — отправка из них прямо скажет, что появится в
    спринте 06.

### Что уже работает, а что нет

| | |
| --- | --- |
| Чтение, поиск, темы, избранное, хранилище | работает |
| Синхронизация Gmail (вручную и при запуске) | работает |
| Отправка и ответы из Gmail | работает |
| Отправка из Яндекса / Mail.ru / Outlook / IMAP | нет — спринт 06 |

| Фоновая синхронизация, уведомления | нет — спринт 07 |

## Обновление до новой сборки

Автообновления у тестовой сборки нет. Скачайте новый APK тем же способом и
установите поверх: данные (письма, темы, аккаунты, токены) сохраняются, потому
что подпись и package id не меняются.

Если Android откажется устанавливать («приложение не установлено»):

* удалите старую версию (данные при этом потеряются) — обычно это значит, что
  предыдущая сборка была подписана другим ключом;
* либо соберите обе сборки сами: debug-APK всегда подписан вашим
  `~/.android/debug.keystore`.

---

## Удаление

Долгое нажатие на иконку → «Удалить». Локальные письма исчезнут вместе с
приложением; в почтовом ящике ничего не изменится. Токены в Keychain/Keystore
удаляются вместе с приложением.
