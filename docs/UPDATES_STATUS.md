### Установка APK — ✅ без новой зависимости

Важное решение. Обычный путь — плагин `open_filex`, но:

* его свежие версии требуют Dart 3.11+/Flutter 3.35, а сборка идёт на
  Flutter 3.24.5 — `flutter pub get` мог бы не разрешиться;
* старые версии собраны под Gradle-плагин Flutter 3.29+ — ровно та поломка,
  что уже была с `app_links` и стоила нескольких сборок;
* pub.dev из среды разработки недоступен, проверить версию заранее нельзя.

Поэтому установка сделана своим кодом: `MethodChannel`
`app.mellow/apk_installer` и Java-класс `ApkInstallerPlugin`, который пишет
`tool/platform/prepare_android.py` рядом с генерируемым проектом. Плюс
`FileProvider` с authority `app.mellow.updates`, потому что Android не
принимает `file://`.

Что это дало на практике: APK собирается, три задачи CI зелёные, и в сборке
`build-a1b166c` установщик уже внутри. Минус — код на Java в репозитории,
но он читается и проверяется, в отличие от чужой зависимости.

### Как проверить обновление на телефоне

Нужны две сборки: одна установленная, вторая новее. Порядок:

1. Поставьте текущую сборку: релиз `build-a1b166c`, файл
   `mellow-a1b166c-debug.apk`. Разрешите установку из этого источника.
2. Откройте Mellow: плашки быть не должно — GitHub считает эту сборку
   последней.
3. Попросите меня собрать следующую (любой новый коммит), например
   скажите «сделай коммит» — CI опубликует `build-<новый sha>`.
4. Откройте Mellow. **В течение ~5 секунд** над списком диалогов должна
   появиться плашка «Доступно обновление».
5. «Обновить» → «Скачать»: пойдёт прогресс, видно «47% · 91 МБ из 194 МБ».
6. По завершении — «Установить». Android спросит разрешение
   «Устанавливать из неизвестных источников» — это ожидаемо, приложение
   даст кнопку в нужный экран настроек.
7. После установки: аккаунты, письма, тема и избранное на месте,
   в «О приложении» — новый sha, плашки нет.

Пункты 4 и 6 — то, чего я не могу проверить из репозитория: нужен живой
телефон и реальное нажатие в системном диалоге Android.

## 10. Риски, о которых лучше знать заранее

| Риск | Почему важно |
| --- | --- |
| **Подпись APK** | debug-keystore генерируется заново на каждом раннере, поэтому новая сборка может быть подписана иначе. Тогда Android откажется ставить её поверх и предложит удалить приложение — с потерей данных. ТЗ §7 требует стабильный keystore в секретах; это **следующий шаг**, до первой реальной проверки обновления на телефоне |
| Размер APK ~194 МБ | загрузка по мобильной сети дорогая → настройка «только Wi-Fi» не украшение, а необходимость |
| GitHub rate limit: 60 запросов/час на IP | при проверке на каждом старте можно упереться → отсюда правило «не чаще 6 ч» |
| Android 8+ требует разрешения на установку из неизвестных источников | без `REQUEST_INSTALL_PACKAGES` установка молча не начинается |
