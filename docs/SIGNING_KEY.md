# Как сохранить ключ подписи (одна операция, один раз)

Без этого шага приложение **скачает** обновление, но Android откажется его
ставить: сборки подписаны разными ключами. Подробности — `UPDATES.md` §7.2.

Всё, что нужно: создать секрет `MELLOW_DEBUG_KEYSTORE_B64` в настройках
репозитория. Два способа — выберите тот, где вам удобнее.

---

## Способ 1. Через сайт GitHub (терминал не нужен)

Годится, если у вас нет компьютера с терминалом под рукой.

### Шаг 1. Получите строку ключа

Ключ состоит из двух частей: **файл** и **длинная строка base64**. Обе создаёт
один скрипт.

**Вариант А — у вас есть терминал на компьютере** (Mac/Linux, либо
WSL/Git Bash на Windows). Из папки репозитория:

```bash
tool/platform/make_signing_key.sh --print-base64
```

Скрипт создаст `build/signing/debug.keystore` и `debug.keystore.pem`, а в
ответ напечатает одну длинную строку — она начинается с `MIIE…`. Её и нужно
скопировать целиком.

**Вариант Б — терминала нет совсем.** Тогда попросите меня: напишите в чат
«сделай ключ и пришли строку». Я выполню скрипт здесь и пришлю строку в ответ.
Это безопасно: ключ попадёт только в ваш секрет GitHub, в репозиторий он не
записывается.

### Шаг 2. Откройте настройки секретов

Ссылка (подставьте свой аккаунт, если форк):

**https://github.com/DippyDingo/MELLOW/settings/secrets/actions**

Или по меню: репозиторий → **Settings** → слева **Secrets and variables** →
**Actions**.

### Шаг 3. Создайте секрет

Нажмите **New repository secret** и заполните два поля:

| Поле | Что вписать |
| --- | --- |
| **Name** | `MELLOW_DEBUG_KEYSTORE_B64` — ровно так, без пробелов |
| **Secret** | длинная строка из шага 1 (`MIIE…`), целиком, одной строкой |

Нажмите **Add secret**. GitHub покажет секрет в списке — значение после
сохранения больше не отображается, это нормально.

### Шаг 4. Пересоберите и проверьте

1. Откройте
   [Actions → Build installable APK](https://github.com/DippyDingo/MELLOW/actions/workflows/build-apk.yml).
2. **Run workflow** → ветка `arena/ef9ea789-mellow` → зелёная кнопка.
3. Когда прогон закончится, откройте его страницу: в блоке **Summary**
   появится «Signing key» с отпечатком `SHA-256 …`.
4. В заметках нового релиза должно быть написано
   «Подпись: постоянный ключ Mellow».

Если написано «debug-ключ раннера (может не встать поверх)» — секрет не
подхватился: проверьте имя (частая ошибка — опечатка или лишний пробел) и что
секрет добавлен именно в этот репозиторий, а не в аккаунт.

## Способ 2. Одной командой в терминале

Если `gh` уже авторизован (`gh auth login`), то из папки репозитория:

```bash
tool/platform/make_signing_key.sh --set-secret
```

Скрипт создаст ключ, сам загрузит его в секреты и напечатает отпечаток.
Дальше — шаг 4 выше.

На Windows запускайте из **Git Bash** (не из cmd/PowerShell): скрипт написан
на bash и использует `openssl`.

---

## Чего делать нельзя

* **Не коммитьте `debug.keystore` и `debug.keystore.pem` в репозиторий.**
  Репозиторий публичный: любой, у кого окажется этот ключ, сможет подписать
  APK, который Android поставит поверх вашего приложения. Папка `build/`
  в `.gitignore`, так что скрипт кладёт файлы в безопасное место — но если
  скопируете их вручную в другое место, следите сами.
* **Не пересоздавайте ключ без нужды.** Новый ключ = приложение придётся
  удалить и поставить заново, а локальные письма при этом исчезнут.

---

## Где хранить `debug.keystore.pem`

Файл `build/signing/debug.keystore.pem` — это сам ключ в читаемом виде.
Скопируйте его в надёжное место (менеджер паролей, приватное облако) и
удалите из папки сборки, если не хотите держать его там.

Зачем: если ключ потеряется, а секрет в GitHub останется — всё продолжит
работать. Но если потерять **и** секрет, восстановить подпись будет нельзя:
пользователям придётся удалять приложение.

Отпечаток ключа (не секрет, можно показывать):

```bash
tool/platform/make_signing_key.sh --fingerprint
```

## Короткая шпаргалка

```
1. tool/platform/make_signing_key.sh --print-base64     ← получить строку
2. github.com/DippyDingo/MELLOW/settings/secrets/actions
3. New repository secret
   Name:   MELLOW_DEBUG_KEYSTORE_B64
   Secret: MIIE…  (вся строка)
4. Actions → Build installable APK → Run workflow
5. В Summary: «Signing key SHA-256 …», в релизе: «постоянный ключ Mellow»
```
