# Безопасность

Приложение получает доступ к личной переписке, поэтому безопасность — не
опция, а часть контракта.

## 1. Секреты

| Что | Где хранится | Где НЕ хранится |
| --- | --- | --- |
| OAuth access/refresh токены | защищённое хранилище ОС (Keychain / Keystore) | SQLite, логи, SharedPreferences |
| Пароли приложений IMAP/SMTP | защищённое хранилище ОС | SQLite, файлы кеша |
| Основной пароль почты | нигде, не запрашивается | — |
| Тела писем | SQLite (локально) | внешние сервисы |

Начиная с Sprint 03 секреты хранит `SecureTokenStorage`
(`lib/domain/security/secure_token_storage.dart`), реализация —
`FlutterSecureTokenStorage`:

* iOS — Keychain с `first_unlock_this_device`: токен доступен после первой
  разблокировки и не уезжает в iCloud-бэкап;
* Android — `EncryptedSharedPreferences`;
* ключи namespaced: `account.<id>.access_token`, `.refresh_token`, `.expires_at`,
  `.app_password` — отключение одного аккаунта не задевает остальные;
* `isAvailable()` делает пробную запись/чтение/удаление: сломанный Keystore
  (бывает после сброса устройства) даёт `false`, а не падение;
* в тестах используется `InMemoryTokenStorage` (в app никогда).

OAuth-поток Gmail:

* PKCE (S256) обязателен — публичный клиент без client secret;
* `state` проверяется на возврате из браузера, иначе
  `AccountAuthException` (защита от подмены redirect);
* `prompt=consent` + `access_type=offline`, чтобы получить refresh-токен;
* refresh-токен перезаписывается только когда Google его прислал — при
  обновлении он не теряется;
* `OAuthTokens.toString()` не печатает токен; тело ответа сервера в сообщения
  об ошибке не попадает (только `error`-код).

Правила:

* `print`/`log` токенов и паролей запрещены; в отладочном выводе — только
  идентификаторы;
* пароль никогда не попадает в текст исключения (`AppException.message` —
  безопасная формулировка);
* тестовые данные используют вымышленные домены (`example.com`) и фиктивные
  идентификаторы.

## 2. Сеть

* Только TLS: IMAP 993, SMTP 465, HTTPS для Gmail/Graph.
* Проверка сертификата не отключается нигде, включая debug.
* Минимальные scopes OAuth (см. `docs/MAIL_PROVIDERS.md`).

## 3. Локальная защита

* `app_lock_enabled` — блокировка приложения (реализация на этапе 07; флаг уже
  сохраняется).
* Данные приложения хранятся в его песочнице; бэкапы вне устройства не
  создаются автоматически.
* «Отключить аккаунт» удаляет локальные письма этого аккаунта и не обращается к
  серверу.

## 4. HTML-письма

Обязательные правила отображения:

1. Активное содержимое (`<script>`, `iframe`, `object`, обработчики событий) не
   исполняется и вырезается санитайзером.
2. Внешние изображения не загружаются при `block_external_images = true`
   (по умолчанию). Пользователь может разрешить загрузку для конкретного письма.
3. `cid:`-изображения подставляются из вложений, не из сети.
4. Ссылки показываются с явным доменом; переход — только по действию
   пользователя.
5. Если санитайзер недоступен, показывается текстовый экран (`bodyText`), а не
   сырой HTML.

## 5. Вложения

* Белый список типов для предпросмотра (изображения, PDF, текст).
* Исполняемые файлы не открываются внутри приложения.
* Проверка размера до скачивания (`AppConstants.maxAttachmentBytes = 20 MB`).
* Файлы кеша — во временном каталоге, очищаются кнопкой «Освободить место».

## 6. Приватность

* Содержимое писем не отправляется третьим сторонам.
* AI-модуль (не входит в MVP) подключается только с согласия пользователя,
  со своим ключом, и полностью отключаем.
* Внешние трекеры в письмах блокируются вместе с изображениями.

## 7. Чек-лист ревью

- [ ] Ни один новый `print` не выводит адреса, тела писем или токены.
- [ ] Новые поля не сохраняют секреты в SQLite.
- [ ] Любой новый сетевой вызов использует TLS и обрабатывает отказ авторизации.
- [ ] Новый путь отображения HTML проходит через санитайзер.
- [ ] Ошибка пользователю сформулирована без внутренних деталей.
