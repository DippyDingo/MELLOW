# Тестирование

## 1. Принципы

* Тест доказывает поведение, а не реализацию.
* Каждая новая функция — минимум три теста: счастливый путь, граница, ошибка.
* Данные в тестах — только вымышленные (`example.com`, `mail.ru` в демо).
* Тесты не ходят в сеть и не зависят от времени: даты передаются явно
  (`now:`), БД — `AppDatabase.inMemory()`.

## 2. Пирамида

| Уровень | Где | Что проверяет |
| --- | --- | --- |
| Unit | `test/core`, `test/domain` | адреса, даты, сущности, discovery, темы |
| Repository | `test/data` | схема, дедупликация, фильтры, миграция настроек |
| State | `test/features` | сохранение и реактивность настроек |
| Widget | `test/app` | запуск, навигация, темы, поиск, вёрстка |
| Integration | `integration_test/` | сквозные сценарии на устройстве (этап 08) |

## 3. Запуск

```bash
flutter test                                        # всё
flutter test test/data/drift_repositories_test.dart # один файл
flutter analyze
```

Для widget-тестов база всегда переопределяется:

```dart
final db = AppDatabase.inMemory();
await DemoSeed.run(db);
final container = createContainer(database: db);
```

## 6. Граничные случаи, которые обязаны оставаться зелёными

1. Повторный сид не дублирует данные.
2. Повторный `upsertMessage` с тем же provider id или Message-ID не создаёт
   вторую строку.
3. Прочитанное сообщение не становится снова непрочитанным после ресинка.
4. Адрес нельзя «украсть» у другого контакта.
5. Удаление основного адреса повышает следующий.
6. Удаление аккаунта удаляет его диалоги, сообщения и вложения.
7. Повреждённое значение настройки не роняет приложение.
8. Пустой список показывает осмысленное состояние, а не пустоту.

## 7. Ручные проверки перед релизом

* Светлая и тёмная темы на всех экранах.
* Поворот экрана и маленький дисплей (360×640).
* Системный масштаб текста 130–160%.
* Офлайн-запуск: экраны открываются из кеша.
* Полный цикл «отключить аккаунт → данные исчезли → сервер не тронут».
