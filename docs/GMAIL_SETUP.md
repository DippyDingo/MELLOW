# Подключение Gmail: почему сейчас не работает и как включить

## Коротко

В сборке, которая у вас установлена, **нет доступа к Google**. Поэтому при
попытке подключить `warmfarm109@gmail.com` приложение показывает экран с
шагами и полем для вставки адреса — но войти не может. Это не ошибка ваших
действий и не «сломанная почта»: в сборку не вложен идентификатор приложения
в Google (OAuth client id), без него Google не показывает экран согласия.

Что нужно: **один раз** зарегистрировать приложение в Google Cloud — около
10 минут, — потом положить идентификатор в настройки репозитория, и все
следующие сборки будут подключать Gmail как обычный вход «через Google».

Пароль от почты при этом не нужен и нигде не хранится: Mellow получает от
Google только токен доступа.

---

## Часть 1. Что делает пользователь после того, как доступ включён

Три нажатия, без вставки ссылок:

1. **Настройки → Почтовые аккаунты → Добавить аккаунт.**
2. Ввести адрес `warmfarm109@gmail.com`. Приложение само понимает, что это
   Gmail, и показывает кнопку «Продолжить».
3. Открывается браузер с экраном Google. Выбрать аккаунт → «Разрешить».
   Браузер возвращается в Mellow сам, письма начинают загружаться.

Поле «вставьте адрес из браузера» остаётся только как страховка: если Android
по какой-то причине не вернул вас в приложение. Тогда — скопировать адрес из
адресной строки и вставить. Это не обязательный шаг.

---

## Часть 2. Что нужно сделать один раз, чтобы это заработало

### Шаг 1. Взять SHA-1 отпечаток ключа подписи

Google требует, чтобы отпечаток ключа, которым подписано приложение, был
зарегистрирован в OAuth-клиенте. Иначе Google откажет с ошибкой
`invalid_request` / «приложение не проверено».

Отпечаток печатает скрипт ключа:

```bash
tool/platform/make_signing_key.sh
```

В выводе будет строка вида:

```
  SHA-1   D5:40:B3:E4:C6:6B:80:00:48:C7:9B:26:6A:57:8D:82:AB:48:6B:4A
```

Она и нужна. **Важно:** это отпечаток ключа, который уже лежит в секрете
`MELLOW_DEBUG_KEYSTORE_B64`. Если ключ пересоздать — отпечаток изменится, и
Google перестанет принимать вход.

### Шаг 2. Создать OAuth-клиент в Google Cloud

1. Откройте <https://console.cloud.google.com/>.
2. Сверху выберите проект (или создайте: **New project** → имя `Mellow`).
3. Меню → **APIs & Services** → **Library** → найдите **Gmail API** →
   **Enable**. Без этого шага письма не загрузятся, хотя вход пройдёт.
4. **APIs & Services** → **OAuth consent screen**:
   * User type: **External**;
   * App name: `Mellow`, support email — ваш;
   * Scopes: добавьте `.../auth/gmail.modify` и `.../auth/gmail.send`;
   * Test users: добавьте `warmfarm109@gmail.com` (и другие свои адреса).
     Пока приложение в режиме Testing, входить могут только эти адреса.
5. **APIs & Services** → **Credentials** → **Create credentials** →
   **OAuth client ID** → тип **Android**:
   * Package name: `app.mellow.mellow`
   * SHA-1: отпечаток из шага 1.
6. Создайте ещё один клиент → тип **iOS** (необязательно, для iPhone).
7. **Важно для мобильного входа:** скопируйте **Client ID** клиента типа
   Android. Он выглядит как `1234567890-abc…apps.googleusercontent.com`.

> Почему Android-клиент, а не «Desktop»: Mellow использует поток PKCE без
> секрета, и Google требует, чтобы redirect URI был
> `com.googleusercontent.apps.<id>:/oauth2redirect` — это схема именно
> мобильного клиента.

### Шаг 3. Положить Client ID в репозиторий

**Settings → Secrets and variables → Actions → Variables → New repository
variable**:

| Поле | Значение |
| --- | --- |
| Name | `GOOGLE_CLIENT_ID` |
| Value | `1234567890-abc…apps.googleusercontent.com` |

Это **variable**, не secret: client id публичен по своей природе (он виден в
адресной строке браузера при входе). Секрета у мобильного клиента нет.

Сборка читает его так: `${{ inputs.google_client_id || vars.GOOGLE_CLIENT_ID }}`,
поэтому id подхватывается и при обычном пуше, и при ручном запуске.

### Шаг 4. Пересобрать и проверить

Actions → **Build installable APK** → **Run workflow** → ветка
`arena/ef9ea789-mellow`. После сборки установите APK и повторите Часть 1.

## Что произойдёт, если что-то не так

| Сообщение Google | Причина | Что делать |
| --- | --- | --- |
| `invalid_request` / «redirect_uri_mismatch» | OAuth-клиент не Android, либо другая схема | создать клиент типа Android с пакетом `app.mellow.mellow` |
| `access_denied` | адрес не добавлен в Test users | добавить адрес в OAuth consent screen |
| «приложение не проверено» | нормально для режима Testing | «Advanced» → «Go to Mellow (unsafe)» |
| Вход прошёл, письма не появились | Gmail API не включён | включить Gmail API в Library |
| В приложении «нет доступа к Google» | в сборке не было `GOOGLE_CLIENT_ID` | шаг 3 и пересборка |

## Часть 3. Для знающих: почему так устроено

* Поток — **OAuth 2.0 Authorization Code + PKCE**, публичный клиент, без
  client secret. Секрет в мобильном приложении бессмысленен: его можно
  извлечь из APK.
* Redirect — пользовательская схема `com.googleusercontent.apps.<id>:/oauth2redirect`.
  Она регистрируется в манифесте патчером `tool/platform/prepare_android.py`,
  а `flutter_deeplinking_enabled=false` не даёт `go_router` перехватить ссылку.
* Токены лежат в Keystore/Keychain через `flutter_secure_storage`, никогда не
  пишутся в логи и не попадают в базу.
* Client id передаётся в сборку через `--dart-define`, поэтому его нет в
  репозитории; `AppConfig.fromEnvironment` читает его при компиляции.
* Пока приложение в режиме Testing, Google ограничивает вход списком Test
  users — публикация (verification) не нужна для личного использования.
* Не «своя» почта: Mellow не хранит пароль и не может читать ящик без токена,
  выданного вами; отзыв доступа — в аккаунте Google, раздел «Сторонние
  приложения».
